# ⚡ نیرا

**دستیار هوش مصنوعی شخصی برای تلگرام، که به‌طور کامل روی Cloudflare Workers اجرا می‌شود.**

نیرا ربات تلگرام شما را به هر سرویس هوش مصنوعی‌ای که انتخاب کنید متصل می‌کند: OpenAI، Anthropic، یا هر سرویس سازگار با OpenAI (OpenRouter، Groq، Ollama و…). کل سامانه یک Worker است؛ بدون مرحلهٔ ساخت، بدون کارسازی که نگهداری کنید و بدون فریم‌ورکی که باید یاد بگیرید. کلیدهای API شما رمزگذاری می‌شوند و بقیهٔ داده‌ها در D1 و KV کلادفلر می‌ماند.

## ⚡ شروع سریع (یک‌کلیکی)

<div dir="ltr">

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/MHDLabs/Nyra)

</div>

دکمهٔ بالا **تنها** نقطهٔ شروع فلوِ یک‌کلیکی است. روی آن بزنید، وارد کلادفلر شوید و چهار ورودی الزامی را پر کنید — نیرا هیچ مقداری نمی‌سازد، پس هر سه اسرار را باید خودتان وارد کنید:

1. **`TELEGRAM_BOT_TOKEN`** — توکن ربات از [@BotFather](https://t.me/BotFather) (قالب `123456789:AA...`).
2. **`TELEGRAM_SECRET`** — رمز تصادفی وب‌هوک؛ همان مقداری که در هدر `X-Setup-Secret` برای `/setup` استفاده می‌شود.
3. **`ENCRYPTION_KEY`** — کلید ۳۲ بایتیِ base64 که همهٔ کلیدهای API ذخیره‌شده را رمزگذاری می‌کند.
4. **`ADMIN_IDS`** — شناسه(های) عددی تلگرام مدیر(ان)، جداشده با کاما (برای دانستن شناسهٔ خودتان هر پیامی به [@userinfobot](https://t.me/userinfobot) بفرستید).
5. **`TAVILY_API_KEY` (اختیاری)** — جست‌وجوی زندهٔ وب را فعال می‌کند. بدون آن، خواندن صفحه‌های عمومی فعال می‌ماند اما جست‌وجو در اختیار مدل قرار نمی‌گیرد. کلید را از Tavily بگیرید و با `npx wrangler secret put TAVILY_API_KEY` ثبت کنید.

دو اسرارِ تصادفی را روی دستگاه خودتان بسازید (مک/لینوکس؛ در ویندوز از WSL یا Git Bash استفاده کنید) و در فرم بچسبانید:

```bash
openssl rand -hex 32      # → TELEGRAM_SECRET   (۶۴ کاراکتر hex، مورد تأیید تلگرام)
openssl rand -base64 32   # → ENCRYPTION_KEY    (هنگام decode دقیقاً ۳۲ بایت)
```

`openssl` ندارید؟ هر مولد رمزنگاریِ امنی کافی است، به شرطی که خروجی با قالب بالا بخواند — مثلاً `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` برای `TELEGRAM_SECRET` و همان دستور با `toString('base64')` برای `ENCRYPTION_KEY`. هرگز توکن ربات، رمز دستیِ خودساخته یا خروجی سایت‌های «رشتهٔ تصادفی» را به‌کار نبرید.

بقیهٔ موارد خودکار است: کلادفلر D1 و KV و صف را از `wrangler.toml` می‌سازد، دامنهٔ `workers.dev` فعال می‌شود و خودِ Worker وب‌هوک تلگرام را در نخستین تماس ثبت می‌کند — بدون curl و بدون هیچ مرحلهٔ دستی. فلوی استقرار هر چهار ورودی را الزامی نشان می‌دهد (همراه با توضیحِ محل دریافت یا نحوهٔ تولیدشان)؛ صفحهٔ وضعیت (`GET /`) نیز اگر `ADMIN_IDS` خالی یا نامعتبر باشد در زمان اجرا هشدار می‌دهد و تا معتبرشدن هر سه اسرار، هر درخواست کد ۵۰۰ برمی‌گرداند.

جست‌وجوی زندهٔ وب به راز اختیاری `TAVILY_API_KEY` نیاز دارد. تنظیم Workers AI در پنل مدیریت سه حالت خاموش، فقط مدیران و همهٔ کاربران مجاز دارد و پیش‌فرض آن خاموش است. در حالت فعال، Workers AI پس از ناموفق‌شدن اتصال‌های ارائه‌دهندهٔ کاربر به‌عنوان مسیر جایگزین گفتگو به کار می‌رود؛ شناسهٔ مدل `@cf/...` نیز از پنل قابل تغییر است.

ترجیح می‌دهید از خط فرمان بروید؟ مسیر دستی کامل در [راه‌اندازی](#-راه‌اندازی) → *گزینهٔ ب* آمده است.

## ✨ امکانات

- **🚀 بدون زیرساخت** — یک Worker، یک پایگاهٔ دادهٔ D1 و یک فضای KV. نه کارسازی، نه ساخت پروژه.
- **🔀 هر سرویس‌دهنده‌ای** — API سازگار با OpenAI (با آدرس پایهٔ دلخواه) و Anthropic؛ پاسخ‌ها به‌صورت جریانی می‌آیند و همزمان در گفتگو ویرایش می‌شوند.
- **👥 اتصال‌های چندگانه** — مدیر مدل‌های سراسری تعریف می‌کند؛ کاربران هم می‌توانند اتصال شخصی بسازند، در هر گفتگو مدل عوض کنند و مدل پیش‌فرض شخصی تعیین کنند.
- **🔐 کلیدهای رمزگذاری‌شده** — کلیدهای API با الگوریتم AES-256-GCM (با مشتق‌گیری HKDF برای هر مالک) رمزگذاری می‌شوند و هرگز به‌صورت متن ساده در پایگاهٔ داده ذخیره نمی‌شوند.
- **🛟 بازخودکار خودکار** — اگر اتصالی خطا بدهد یا timeouts شود، نیرا دوباره تلاش می‌کند و در بازهٔ زمانی مشخص به اتصال‌های فعال دیگر می‌رود.
- **🧠 حافظه** — حافظهٔ ماندگار برای هر کاربر با سه حالت (عادی، کمینه، خاموش)، فرمان‌های صریح `/remember` و `/forget`، و جمع‌بندی دوره‌ای خاطرات.
- **🎭 شخصیت‌ها** — هفت شخصیت پیش‌فرض (عادی، دوست، شوخ، نیرای رمانتیک، حرفه‌ای، برنامه‌نویس، خلاق) به‌علاوهٔ تا ۱۰ شخصیت سفارشی برای هر کاربر.
- **👥 پشتیبانی از گروه** — در گروه‌ها نیرا فقط وقتی پاسخ می‌دهد که نامش برده شود (Nyra / نیرا / نيرا) یا به یکی از پیام‌هایش پاسخ دهید؛ زمینهٔ گفتگو برای هر رشتهٔ پیام جداگانه نگهداری می‌شود.
- **🛡️ محدودیت نرخ و مسدودسازی** — محدودیت برای هر کاربر، هر گفتگو و هر مدیر، به‌علاوهٔ فهرست مسدود مدیر.
- **🛠️ پنل مدیریت** — مدیریت کاربران، گفتگوها، حالت گروه‌ها، اتصال‌ها و فهرست مسدود، و مشاهدهٔ آمار و وضعیت سامانه؛ همه به‌صورت دکمه‌ای داخل خود تلگرام.

## 📁 ساختار پروژه

ربات به ماژول‌های کوچک و مستقل ES در پوشهٔ `src/` تقسیم شده است — Wrangler آن‌ها را خودکار بسته‌بندی می‌کند و همچنان نیازی به مرحلهٔ ساخت نیست. هر پوشه‌ای که `index.js` (بشکه) دارد، یک ماژول نازکِ هم‌نام در کنارش هست که فقط بازصدور می‌کند، بنابراین مسیر import هیچ فراخوان یا آزمونی لازم نشد عوض شود:

```
src/
├── index.js        نقطهٔ ورود Worker (ریشهٔ ترکیب): fetch / scheduled / queue
├── config.js       ثابت‌های مشترک، قواعد prompt، شخصیت‌های پیش‌فرض
├── utils.js        ابزارهای خالص، پاک‌سازی ورودی‌ها، محدودسازی نرخ
├── crypto.js       رمزگذاری AES-256-GCM، اعتبارسنجی اسرار الزامی
├── telegram.js     لایهٔ Bot API تلگرام، ثبت وب‌هوک و دکمهٔ منو
├── brain.js        مونتاژ prompt و انتخاب مدل
├── memory.js       داده‌های حافظه، system promptها، شخصیت‌ها، جمع‌بندی
├── formatter.js    رندر HTML تلگرام و تقسیم پیام
├── menus.js        صفحه‌های تنظیمات و نماهای درون‌خطی
├── commands.js     فرمان‌های کاربری و پنل مدیریت
├── reactions.js    طبقه‌بندی احساسات با Workers AI
├── broadcast.js    کمپین‌های پیام‌رسانی گروهی
├── dlq.js          ثبت و بازپخش به‌روزرسانی‌های شکست‌خورده
├── handlers/       پردازش به‌روزرسانی (وب‌هوک ← صف ← مسیر تند / callback / AI)
├── flows/          جادوگرهای افزودن/ویرایش اتصال و مسیر
├── miniapp/        API جیسونِ مینی‌اپ پشت `/api/*`
├── db/             ساختار D1، مهاجرت‌های نسخه‌بندی‌شده و همهٔ کوئری‌ها
├── providers/      کلاینت‌های OpenAI-سازگار و Anthropic، پخش جریانی، بازخودکار
├── ai.js           → بازصدور providers/
├── db.js           → بازصدور db/
├── flows.js        → بازصدور flows/
└── miniapp.js      → بازصدور miniapp/

public/             خودِ مینی‌اپ (بدون مرحلهٔ ساخت، مستقیم از کلادفلر سرو می‌شود)
scripts/            کاوشِ پس از استقرار + تقسیم‌کنندهٔ مکانیکی ماژول
  postdeploy.mjs    کاوش وضعیت پس از استقرار
  split-module.mjs  ابزار بازآرایی که پوشه‌های بالا را ساخت
test/               تست‌رانر داخلی Node، بدون هیچ وابستگی
```

### فایل‌های ایستا

مینی‌اپ در `./public` **درون بستهٔ Worker جای نمی‌گیرد**. در `wrangler.toml` یک اتصال بومی `[assets]` تعریف شده، پس کلادفلر `public/index.html` و `public/app.js` و `public/styles.css` را مستقیم از لایهٔ فایل ایستای خودش سرو می‌کند. مقدار `run_worker_first = ["/webhook", "/setup", "/status", "/api/*"]` وب‌هوک، مسیر setup، صفحهٔ وضعیت و API جیسون را در اختیار Worker نگه می‌دارد؛ هر مسیر دیگری بدون بیدار کردن Worker از `public` سرو می‌شود. اتصال `ASSETS` را کد نمی‌خواند — وجودش فقط برای این است که Wrangler لایهٔ فایل ایستا را به این Worker بچسباند.

## 📋 پیش‌نیازها

- حساب [کلادفلر](https://dash.cloudflare.com) (پلن رایگان کافی است — Workers و D1 و KV و Queues همه روی پلن رایگان کار می‌کنند؛ رایگان Queues شامل ۱۰٬۰۰۰ عملیات در روز است که برای استفادهٔ شخصی/گروه‌های کوچک کافی است)
- توکن ربات تلگرام از [@BotFather](https://t.me/BotFather)
- کلید API از یک سرویس هوش مصنوعی (سازگار با OpenAI یا Anthropic)
- **دکمهٔ یک‌کلیکی:** چیزی فراتر از توکن ربات، دو اسرارِ تولیدی و شناسهٔ مدیر لازم نیست
- فقط برای راه‌اندازی دستی: [Node.js](https://nodejs.org) و ابزار خط فرمان [Wrangler](https://developers.cloudflare.com/workers/wrangler/)

## 🚀 راه‌اندازی

### گزینهٔ الف — یک‌کلیکی (پیشنهادی)

از دکمهٔ **Deploy to Cloudflare** در بخش [شروع سریع](#-شروع-سریع-یک‌کلیکی) استفاده کنید — تنها نقطهٔ ورود فلوِ یک‌کلیکی همان است.

1. روی دکمه بزنید و وارد کلادفلر شوید.
2. فلو چهار ورودی الزامی می‌خواهد — هیچ مقداری خودکار ساخته یا مشتق نمی‌شود:
   - `TELEGRAM_BOT_TOKEN` — توکن از @BotFather.
   - `TELEGRAM_SECRET` — خروجی `openssl rand -hex 32`.
   - `ENCRYPTION_KEY` — خروجی `openssl rand -base64 32`.
   - `ADMIN_IDS` — شناسه(های) عددی تلگرام مدیر(ان)، جداشده با کاما.
3. **Deploy** را بزنید. کلادفلر D1 و KV و صف را از `wrangler.toml` می‌سازد، دامنهٔ `nyra.<subdomain>.workers.dev` را فعال می‌کند و اسکریپت استقرار را اجرا می‌کند که با یک کاوشِ صفحهٔ وضعیت پایان می‌یابد.
4. خودِ Worker راه‌اندازی می‌کند: نخستین تماس پایگاهٔ داده را می‌سازد و **وب‌هوک تلگرام را خودکار ثبت می‌کند** — بدون curl و بدون مرحلهٔ دستی. برای اطمینان یک بار `https://nyra.<your-subdomain>.workers.dev/status` را باز کنید؛ باید `Webhook: registered → …` و `Admin IDs: 1 configured` را ببینید. (`/` خودِ مینی‌اپ است، نه صفحهٔ وضعیت.)
5. در گفتگوی خصوصی با ربات `/start` بفرستید و سپس مدل را وصل کنید (*گزینهٔ ب، مرحلهٔ ۶*).

نکته‌ها:
- cron تعبیه‌شده هر چند دقیقه ثبت وب‌هوک را دوباره بررسی می‌کند، پس اگر ثبت سمت تلگرام از بین برود خودترمیم می‌شود.
- ارتقای نصب موجود؟ `database_id` / `id` واقعی را در `wrangler.toml` نگه دارید و همان `TELEGRAM_SECRET` / `ENCRYPTION_KEY` فعلی‌تان را هم — تغییر `ENCRYPTION_KEY` کلیدهای API ذخیره‌شده را ناخوانا می‌کند و تغییر `TELEGRAM_SECRET` نیازمند ثبت دوبارهٔ وب‌هوک است.

### گزینهٔ ب — راه‌اندازی دستی با خط فرمان

#### ۱. ساخت ربات

به [@BotFather](https://t.me/BotFather) پیام دهید، دستور `/newbot` را بفرستید و توکنی را که می‌دهد نگه دارید.

#### ۲. فضای ذخیره‌سازی (خودکار)

چیزی لازم نیست دستی بسازید: در `wrangler.toml` پایگاهٔ دادهٔ D1، فضای KV و صف `nyra-updates` **بدون شناسهٔ منبع** تعریف شده‌اند، بنابراین provisioning خودکار Wrangler هر سه را در نخستین `wrangler deploy` می‌سازد و شناسه‌هایشان را در همان `wrangler.toml` می‌نویسد.

> **ارتقای نصب موجود؟** اگر `wrangler.toml` شما هم‌اکنون `database_id` یا `id` واقعی دارد، آن مقادیر را نگه دارید — حذفشان کنید منابعی **جدید و خالی** می‌سازد.

ساخت دستی (`wrangler d1 create nyra`، `wrangler kv namespace create KV`) همچنان ممکن است: شناسه‌های خروجی را در `wrangler.toml` وارد کنید.

#### ۳. تنظیم اسرار

هر سه الزامی هستند. اول دو مقدار تصادفی را بسازید، بعد هر سه را ثبت کنید:

```bash
openssl rand -hex 32       # → مقداری که برای TELEGRAM_SECRET استفاده می‌کنید
openssl rand -base64 32    # → مقداری که برای ENCRYPTION_KEY استفاده می‌کنید

wrangler secret put TELEGRAM_BOT_TOKEN   # توکن @BotFather را بچسبانید
wrangler secret put TELEGRAM_SECRET      # خروجی `openssl rand -hex 32` را بچسبانید
wrangler secret put ENCRYPTION_KEY       # خروجی `openssl rand -base64 32` را بچسبانید
```

`ENCRYPTION_KEY` باید هنگام decode دقیقاً ۳۲ بایت باشد؛ `TELEGRAM_SECRET` می‌تواند شامل `A-Z a-z 0-9 _ -` باشد (hex در چارک‌تر تلگرام جا می‌گیرد). هر دو را جای امنی نگه دارید — اگر هر کدام خالی یا نامعتبر باشد، Worker به هر درخواست کد ۵۰۰ می‌دهد و تغییر `ENCRYPTION_KEY` کلیدهای API ذخیره‌شده را غیرقابل‌رمزگشایی می‌کند.

شناسهٔ تلگرام خود (یا مدیران) را به‌عنوان عدد در `wrangler.toml` و بخش `[vars] → ADMIN_IDS` وارد کنید (برای چند مدیر با کاما جدا کنید).

#### ۴. انتشار

```bash
wrangler deploy
```

#### ۵. ثبت وب‌هوک (خودکار؛ `/setup` برای دستی)

هیچ مرحلهٔ دستی لازم نیست: کاوشِ پس از استقرار، هر درخواستِ رسیده به Worker، یا نخستین بازدید `GET /status` وب‌هوک را با رمزِ زمانِ اجرا ثبت می‌کند و cron دوباره بررسی‌اش می‌کند. برای ثبت دستی یک بار اجرا کنید (رمز **فقط در هدر** می‌رود، هرگز در نشانی):

```bash
curl -H "X-Setup-Secret: <TELEGRAM_SECRET>" \
  "https://<your-worker>.workers.dev/setup?url=https://<your-worker>.workers.dev/webhook"
```

پاسخ JSON با `"ok": true` یعنی نیرا بالا آمده است. ربات را در تلگرام باز کنید و `/start` بفرستید.

نکته‌ها:
- رمز در رشتهٔ پرسوجو (`?secret=…`) پذیرفته نمی‌شود — رمز در نشانی‌ها به لاگ‌ها و تاریخچهٔ مرورگر نشت می‌کند.
- مسیر دستی `/setup` با `drop_pending_updates: true` ثبت می‌کند (به‌روزرسانی‌های جمع‌شده حذف می‌شوند)؛ مسیر خودکار این‌طور نیست.

#### ۶. اتصال مدل

در گفتگوی خصوصی با ربات، وارد `/admin` ← **Connections** شوید و یک سرویس‌دهنده اضافه کنید (سازگار با OpenAI به‌همراه آدرس پایه، یا Anthropic)، سپس کلید API و نام مدل را وارد کنید. تست را همان‌جا بزنید و مدل را به‌عنوان پیش‌فرض سراسری انتخاب کنید.

| `TELEGRAM_SECRET` | ✅ | رمزی که تلگرام با هر فراخوانی می‌فرستد؛ دروازهٔ دسترسی `/setup` هم هست. با `openssl rand -hex 32` بسازید. هیچ مشتق‌گیری‌ای نیست — بدون آن Worker کد ۵۰۰ می‌دهد |
| `ENCRYPTION_KEY` | ✅ | کلید ۳۲ بایتیِ base64 برای AES-256-GCM روی کلیدهای API ذخیره‌شده. با `openssl rand -base64 32` بسازید. باید دقیقاً ۳۲ بایت decode شود |
| `ADMIN_IDS` | ✅ | شناسه(های) عددی مدیران تلگرام، جداشده با کاما (در دکمهٔ استقرار پرسیده می‌شود) |
| `TELEGRAM_BOT_ID` / `TELEGRAM_BOT_USERNAME` | اختیاری | هویت کش‌شدهٔ ربات؛ در صورت خالی‌بودن خودکار دریافت می‌شود |

اتصال D1 با نام `DB`، KV با نام `KV` و صف به‌روزرسانی‌ها با نام `NYRA_QUEUE` است (در `wrangler.toml`). مسیر به‌روزرسانی: تلگرام ← وب‌هوک (بلافاصله پس از اعتبارسنجی و حذف `update_id`های تکراری پاسخ می‌گیرد) ← صف ← مصرف‌کننده، که کل خط لولهٔ AI را اجرا می‌کند — بنابراین پاسخ‌های جریانیِ بلند قربانی محدودیت ۳۰ ثانیهٔ پس از پاسخِ درخواست وب‌هوک نمی‌شوند.

ساختار پایگاهٔ داده در نخستین استفاده ساخته می‌شود — از راه صفحهٔ وضعیت، نخستین وب‌هوک یا کاوشِ cron (همه با دروازهٔ KV، پس D1 پس از راه‌اندازی آرام می‌ماند)؛ مهاجرت‌های یک‌بارمصرف نسخه‌بندی شده و در جدول `schema_migrations` ثبت می‌شوند. نشانی وب‌هوک از نخستین درخواستی که به Worker می‌رسد آموخته می‌شود — در عمل `GET /status`، چون `/` توسط لایهٔ فایل ایستا سرو می‌شود و هرگز به کد نمی‌رسد — و cron هر ۵ دقیقه خودکار دوباره بررسی‌اش می‌کند (`ensureWebhook` در `src/telegram.js`).

## 🔐 نکات امنیتی

- پیام‌های وب‌هوک بدون رمزِ وب‌هوک (`TELEGRAM_SECRET`) پذیرفته نمی‌شوند و مقایسهٔ رمز به‌صورت زمان ثابت انجام می‌گیرد. به‌روزرسانی‌های تکراری پیش از پردازش با `update_id` حذف می‌شوند.
- کلیدهای API با AES-256-GCM و کلیدهایی رمزگذاری می‌شوند که از `ENCRYPTION_KEY` شما برای هر مالک مشتق شده‌اند.
- **همهٔ اسرار صریح‌اند.** هیچ مقداری از توکن ربات مشتق نمی‌شود، پس دستیابی به توکن رمز وب‌هوک یا کلید اصلی را لو نمی‌دهد. هر اسرار مستقل است: `TELEGRAM_SECRET` را هر وقت خواستید بچرخانید (و بعد وب‌هوک را دوباره ثبت کنید)، اما `ENCRYPTION_KEY` را دائمی بدانید — تغییرش همهٔ کلیدهای API ذخیره‌شده را غیرقابل‌رمزگشایی می‌کند.
- **Worker از کار با پیکربندی ناقص سر باز می‌زند.** اگر `TELEGRAM_BOT_TOKEN`، `TELEGRAM_SECRET` یا `ENCRYPTION_KEY` خالی یا نامعتبر باشد، هر درخواست کد ۵۰۰ (`Server misconfigured: …`) می‌گیرد و نام دقیق مقدار گمشده در لاگ می‌آید — به‌جای اینکه بی‌صدا با کلید ضعیف یا غایب بالا بیاید.
- مسیر `/setup` محدودیت نرخ دارد، رمز را فقط در هدر `X-Setup-Secret` می‌پذیرد (رمز در پرسوجو رد می‌شود) و فقط نشانی‌ای روی همان میزبان با مسیر دقیق `/webhook` را می‌پذیرد.
- محدودیت‌های نرخ بهترین تلاش هستند: بر پایهٔ KV (با همگردانی تأخیری در نواحی لبه) و در صورت ازدست‌بودن KV باز می‌مانند — ترجیح دسترس‌پذیری بر سخت‌گیری.
- **ذخیرهٔ داده:** حافظه و تاریخچهٔ گفتگو در D1 کلادفلر نگهداری می‌شوند. اسرار رمزگذاری شده‌اند؛ حافظه/گفتگوها به‌صورت رمزننشده ذخیره می‌شوند و برای کسی که به D1 حساب کلادفلر شما دسترسی دارد خوانا هستند. خود برنامه هرگز حافظه یا گفتگوی یک کاربر را — حتی برای مدیران — به کاربر دیگری نشان نمی‌دهد.
- اسرار محلی در پروندهٔ `.dev.vars` نگهداری می‌شوند (در git نادیده گرفته می‌شود) — نمونه در `.dev.vars.example`؛ هر سه اسرار آنجا هم الزامی‌اند.
- اگر هر یک از سه اسرار خالی یا نامعتبر باشد، Worker درخواست‌ها را پردازش نمی‌کند (تابع `validateSecrets` در `src/crypto.js`).
